1. 이번 구현의 목표와 현재 도달한 지점

LG M50 가상 셀을 만들어 5 EFC에서 초기 성능을 A·B·C로 구분하고, 첫 100 EFC의 관측 기록으로 SOH 80%까지 남은 수명을 예측한다. 충전 전류는 3.0·3.1·3.2·3.3 A를 비교하며, 20→80% 충전을 60분 안에 마치는 후보 중 수명에 유리한 값을 베이지안 최적화로 찾는다. 첫 버전의 학습 출력은 잔여 수명 RUL 하나다. SOC와 SOH는 물리 계산과 기준시험으로 구하며 별도의 SOC·SOH 신경망은 추가하지 않는다.

현재는 분할 계산의 짧은 검증 결과가 보고된 단계다. 3.0 A의 CC→CV 전환과 SOC 종료, 마지막 상태만 넘기는 계산은 짧은 사례에서 작동했다. 하지만 기준시험 용량 Q₀는 아직 확보되지 않았고 분할 계산의 열화 상태 오차와 진단 분기의 상태 보존도 추가 확인이 필요하다. 다음 구현은 이 항목을 끝내는 데 집중한다. 200개 셀의 전체 수명 계산을 바로 시작하지 않는다.

이 문서는 사용자가 제공한 코딩 에이전트의 모델링 결정 기록을 기준으로 작성했다. 아래의 실행 수치는 해당 기록에 보고된 결과이며, 이 문서 작성 과정에서 원시 report.json을 대조하거나 계산을 재실행한 것은 아니다. 실제 프로젝트에서는 원시 보고서, 로그, 코드 버전, 설정과 환경 정보를 함께 보존한다. 소스에 기능이 존재한다는 사실, 짧은 사례에서 실행됐다는 사실, 장기 계산까지 검증됐다는 사실을 구분한다.

기존 합의 수치는 유지한다. 공통 1.5 A 실험에서 초기 등급을 따로 측정하는 방식과 원격 추론 시연은 기존 작성안의 설계안으로 남긴다. 학습 코드 작성자는 코딩 에이전트다. 이번 수정본에서는 이미 설치된 환경에 맞춰 PyTorch를 학습 구현의 기본안으로 사용한다. 클라우드 제공자는 정하지 않는다.

2. 환경과 실험 설정

제공 기록의 환경은 Python 3.11, PyBaMM 26.8.0.0, pybammsolvers 0.9.1, CasADi 3.7.2, NumPy 2.4.6, SciPy 1.17.1, pandas 3.0.5, matplotlib 3.11.2, pyarrow 26.0.0, torch 2.14.1+cpu, scikit-learn 1.9.1이다. requirements.txt와 실제 실행 환경을 대조하고 Python의 세부 버전, 설치 출처, 플랫폼 정보도 실행 명세에 남긴다. 이미 설치한 패키지를 이유 없이 다시 설치하지 않는다.

환경 점검, import, 짧은 SPMe 계산, pip check 통과가 보고됐다. 이 결과를 전체 열화 조합이나 클라우드 GPU 환경의 검증으로 확대하지 않는다. 의존성 변경 전후에는 같은 입력으로 기준 계산을 비교한다. setuptools 같은 도구의 변경도 기록하되 영향이 전혀 없다고 단정하지 않는다. 클라우드에서는 CPU 전용 torch 패키지를 그대로 강제하지 말고 호환되는 GPU 실행 환경을 별도로 고정한다.

실험 수치와 난수 시드는 설정 파일에 둔다. 물리 모델 설정, 가상 셀 목록, 운전 조건, 진단 조건, 저장 규칙, 학습·최적화 설정을 구분하고 최종 적용된 설정을 각 결과 폴더에 저장한다. 예전 충전 제어 방식과 폐기된 열화 옵션의 로그는 이력으로 분리한다. 현재 운전은 CC–CV로 통일하며 이전 실험의 계수나 성능 추정을 가져오지 않는다.

3. 물리 모델과 셀별 파라미터

SPMe와 OKane2022를 사용한다. 셀은 등온 298.15 K, 즉 25°C에 고정한다. SEI는 solvent-diffusion limited, 리튬 도금은 partially reversible, SEI film resistance는 distributed다. SEI porosity change와 lithium plating porosity change는 각각 true로 명시한다. 균열, 균열 표면 SEI, 활성물질 손실은 제외하고 해당 옵션도 명시한다.

SEI를 켠 상태의 막 저항 기본값이 distributed라는 소스 확인이 보고됐다. 이를 명시하는 것은 막 저항을 하나 더 추가한다는 뜻이 아니다. 두 기공률 옵션은 각각 존재하며 설치 소스에서 확인되지 않은 별칭 관계를 전제하지 않는다. 실제 방정식에 SEI·도금의 기공률 기여가 들어가는지 확인하고 별도 수식으로 같은 효과를 다시 더하지 않는다.

음극 입자 반지름과 SEI 용매 확산계수만 셀마다 바꾼다. 반지름 기준은 5.86×10⁻⁶ m이며 범위는 5.274×10⁻⁶~6.446×10⁻⁶ m다. 확산계수 기준은 2.5×10⁻²² m²/s이며 범위는 2.5×10⁻²²~2.5×10⁻²¹ m²/s다. 다른 열화 계수는 설치 OKane2022 값을 유지한다. 도금 속도 상수의 보고값은 1×10⁻⁹ m/s다. 실행마다 전체 파라미터와 기준 대비 배율을 보존한다.

예비 9개 조합은 반지름 5.274·5.860·6.446 μm 각각에 확산계수 2.5×10⁻²²·7.5×10⁻²²·2.5×10⁻²¹ m²/s를 연결한 것이다. 반지름을 먼저 고정하고 확산계수를 순서대로 배치하면 4번이 기준값 셀이다. 이 범위는 민감도 실험용이며 실제 제조 편차를 측정한 분포가 아니다.

본 데이터의 목표는 예비 조합과 별도로 원본 셀 200개다. 고정 시드 Latin hypercube로 반지름은 선형 구간, 확산계수는 로그 구간에서 생성한다. 학습 120개, 검증 40개, 최종 시험 40개로 원본 셀을 먼저 나눈다. 같은 셀의 네 전류, 진단, 등급 실험, 압축 시퀀스는 같은 분할에 둔다. 200개×네 전류는 최대 800개 궤적이며 독립 셀 800개가 아니다. 첫 학습용 20개는 학습 120개 안에서 고정 선택한다.

4. 일상 운전과 CC–CV 제어

일상 운전은 SOC 20%에서 시작해 충전 20→80%, 휴지 5분, 5 A 방전 80→20%, 휴지 5분을 반복한다. 1.5 A는 공통 비교·등급 실험용이다. 최적화 궤적의 CC 설정은 3.0·3.1·3.2·3.3 A 중 하나로 수명 실험 내내 고정한다. CV에서 실제 전류가 감소하는 것은 이 조건과 모순되지 않는다. SOH에 따른 전류 재선택은 후속 버전으로 둔다.

본 계산과 진단 모두 Experiment를 사용한다. CC·방전·휴지는 전류 단계로, CV는 4.2 V 전압 유지 단계로 계산한다. CC 충전은 SOC 80%와 4.2 V 중 먼저 도달한 이벤트에서 끝난다. SOC가 먼저면 CV를 건너뛰고 휴지로 이동한다. 전압이 먼저이고 SOC가 80% 미만이면 CV로 전환해 SOC 80%에서 종료한다. SOC 경계를 갱신해 이미 목표에 도달한 경우에도 추가 CV를 수행하지 않는다. [PyBaMM 단계·사용자 정의 종료 예제](https://docs.pybamm.org/en/pybamm-v26.8.0.0/source/examples/notebooks/simulations_and_experiments/custom-experiments.html)

방전 하한은 2.5 V다. SOC 20%보다 전압 하한에 먼저 도달하면 운전 조건 미충족으로 기록한다. CV에서 SOC에 도달하지 못하고 진행이 정체되는 경우도 성공으로 처리하지 않는다. 종료 이벤트, 실제 진행 시간, 종료 원인을 매 조각 확인한다. 종료된 해를 다시 넘겼는데 시간이 진행하지 않는 경우 반복 루프를 계속 돌리지 않는다.

60분 목표는 네 최적화 전류에만 적용하며 충전 시작부터 SOC 80%까지의 CC와 CV 시간을 합한다. 이후 휴지는 제외한다. 수명 전체의 매 충전에 적용한다. 시간 초과 후보도 물리 계산이 유효하면 수명 정답을 얻기 위해 계속 계산할 수 있지만 추천 후보에서는 제외한다.

제공된 기준값 셀의 첫 충전은 3.0 A CC 60.2분 후 4.2 V에 도달하고 CV 1.3분을 더해 총 61.5분이었다. 평형 창 용량은 5.1099 Ah로 보고됐으며 충전량은 3.0732 Ah였다. 따라서 이 셀의 3.0 A는 추천 불가다. 이는 CC–CV 구현 실패가 아니라 시간 조건 실패다. 다른 셀·전류까지 같은 결과로 단정하지 않는다. 3.0 A는 하단 비교 후보로 유지하고 범위·SOC·시간 기준을 통과에 맞춰 바꾸지 않는다. 네 후보가 모두 실패하면 추천 가능한 후보 없음으로 반환한다.

5. SOC와 SOH와 EFC

SOC는 현재 평형 경계에 대한 평균 음극 화학양론의 위치다. x에 Average negative particle stoichiometry를 사용하고 SOC=(x−x₀)/(x₁₀₀−x₀)로 계산한다. 제공 소스 기록은 이 변수가 음극 두께 방향과 입자 반지름 방향을 평균한 농도를 최대 농도로 나눈 값이라고 설명한다. 입자 표면 농도로 대체하지 않는다.

eSOH 입력은 현재 Negative electrode capacity [A.h], Positive electrode capacity [A.h], Total lithium in particles [mol]×F/3600이다. 전해질까지 포함한 전체 리튬량이나 초기 리튬량을 반복해서 넣지 않는다. 출력의 x_0와 x_100으로 경계를 구한다. 평형 전압 기준은 OCV 0%에서 2.5 V, 100%에서 4.2 V다. 최초 SOC 20% 설정은 한 번만 적용하며 분할·주기 전환 때 농도와 열화 상태를 초기화하지 않는다.

경계는 시뮬레이션 시간 60초마다, 충방전 단계 전환과 진단 시작 때 갱신한다. 휴지 중에도 갱신한다. 목표 화학양론은 x₂₀=x₀+0.2(x₁₀₀−x₀), x₈₀=x₀+0.8(x₁₀₀−x₀)다. CustomTermination은 충전에서 x₈₀−x, 방전에서 x−x₂₀가 종료 전 양수이고 종료 시 0이 되도록 구성한다. 구간 경계에서 새 목표가 이미 충족됐다면 상위 제어기가 즉시 단계 종료 여부를 판단한다.

SOC는 내부에서 0~1로 저장한다. 종료 허용오차 ±0.1%p는 내부 단위 ±0.001이며 충전 종료 79.9~80.1%, 방전 종료 19.9~20.1%다. 경계 갱신 간격과 이벤트 검출 간격을 혼동하지 않는다. 9개 조합에서 60초 갱신과 10초 갱신을 비교하고 오차를 만족하지 못하면 사례와 비용을 보고해 간격을 조정한다.

SOH(%)=100×Qref/Q₀다. Q₀는 셀별 초기 기준시험 용량으로 끝까지 고정한다. 수명 종료는 SOH 80%다. SOC용 평형 창 용량과 기준시험에서 측정한 Qref는 별도 값이다. 명목 5 Ah는 C-rate 환산에만 사용한다. 이번에 보고된 평형 창 5.1099 Ah를 Q₀로 대신 넣지 않는다.

EFC는 본 궤적 누적 방전량/Q₀다. 충전량, 진단용 방전량, 별도 등급 실험의 방전량을 해당 수명 궤적에 더하지 않는다. Q₀=5 Ah인 설명용 사례에서 3 Ah 방전은 0.6 EFC다. 현재 보고된 한 주기는 Q₀를 확보하지 않은 상태이므로 정확히 0.6 EFC라고 확정하지 않는다. 같은 최초 셀에서 분기한 네 전류는 같은 초기 Q₀를 사용한다.

6. 분할 계산과 상태 장부

물리 상태는 last_state를 다음 계산으로 넘기고 필요한 구간 출력은 저장한 뒤 참조를 해제한다. 전체 해를 계속 이어붙이는 방식을 장기 운전 기본값으로 사용하지 않는다. 제공 기록에서는 전체 해와 last_state 연결의 짧은 결과가 같았고 100조각에서 보관 상태 크기가 일정했다. 이 결과는 해당 조건의 단기 검증이며 수천 EFC의 메모리 안정성을 보장하는 것은 아니다.

last_state 외의 운전 장부는 RunState로 별도 보존한다. 최소 항목은 원본 셀·궤적 ID, 현재 단계, 절대 시뮬레이션 시각, 다음 경계 갱신 시각, 실제 주기 번호, 충전·CV 시작 시각, 휴지 잔여 시간, 부분 구간과 누적 충방전 Ah·Wh, Q₀, 누적 EFC, 시간 조건 위반 이력, 누적 실행 시간, 조각 수다. 체크포인트에서 물리 상태와 이 장부를 함께 복구한다.

60초 조각을 Experiment 내부 cycle 수와 동일시하지 않는다. 경계 갱신 때 CV가 CC로 돌아가거나 충전 시간이 0으로 재설정되면 안 된다. 경계 갱신, SOC·전압 이벤트, 휴지 종료, 진단 EFC와 같은 다음 예정 지점에 맞춰 실제 조각 길이를 정한다. 입력값 갱신 때문에 모델이 매번 다시 빌드되는지도 측정한다. 불필요한 요약 계산을 줄이는 옵션은 설치 API에서 확인한 뒤 사용한다.

7. 사전 실행 결과의 인정 범위와 남은 검증

제공된 verify_chunking 기록은 기준값 셀, 새 열화 옵션, 25°C, SOC 20%에서 시작한 짧은 검증이다. 해당 코드와 report.json, log.txt를 재현 근거로 연결한다. 문서의 숫자만 복사해 실행 검증을 완료한 것으로 처리하지 않는다.

입력 갱신 시험에서는 같은 빌드 모델의 목표 SOC를 0.2030과 0.2080으로 바꿨을 때 18.44초와 49.16초에 각각 이벤트가 종료됐고 실제 종료 함수값이 0으로 보고됐다. 이는 목표 입력 변경이 이벤트에 반영된 사례다. 실제 운전에서 매 60초 갱신한 x₀·x₁₀₀으로 새 목표가 만들어져 다음 조각에 반영되는지도 기록한다. 외부에서 전달한 값만 출력하는 것으로 대체하지 않는다.

실제 한 주기에서 CC→CV 전환, 갱신 후 CV 유지, SOC 상·하한 종료, RunState의 시간 장부 연결이 보고됐다. 충전 종료 SOC 0.800060은 80.006%로 목표 대비 +0.006%p이며 허용오차 안이다. 이 한 주기 통과를 전체 9개 조합이나 진단 분기 검증 완료로 확대하지 않는다. SOC가 전압보다 먼저 도달해 CV를 건너뛰는 경로도 별도로 확인한다.

600초 연속 계산과 60초×10 연결의 최종 상대 차이는 음극 농도 7.6×10⁻⁷, 양극 농도 1.8×10⁻⁵, 전해질 농도 5.5×10⁻⁸, SEI 두께 5.7×10⁻¹⁰, 도금 리튬 2.9×10⁻⁴, 비활성 리튬 8.5×10⁻⁴, 음극 기공률 1.6×10⁻⁷, LLI 2.9×10⁻⁴로 보고됐다. 도금·비활성 리튬이 0이 아닌 상태를 비교한 점은 유지하되 이 차이를 상태 전달 손실이나 단순 솔버 오차 중 하나로 아직 단정하지 않는다. 8.5×10⁻⁴의 상대 차이는 0.085%이며 SOC의 %p 오차와 다른 지표다.

다음 검증에서는 각 조각 끝과 다음 조각 시작의 물리 상태를 변수별로 비교한다. 같은 제어 모드의 연결과 CC→CV 전환을 나누고, 대수 변수 재초기화와 연속이어야 하는 농도·SEI·도금·기공률을 구분한다. 변수별 최대 절대 차이, 기준값 크기, 상대 차이, 음수·범위 위반, 리튬 수지 오차를 남긴다. 값이 0에 가까우면 상대 차이만으로 판정하지 않는다.

솔버 설정을 기본값, 더 엄격한 값, 한 단계 더 엄격한 값으로 바꿔 같은 연속·분할 계산을 비교한다. 실제 rtol·atol·메시와 비용을 기록하고 공통 출력 시점에서 전압, SOC, 방전량, 열화량의 차이를 확인한다. 오차가 줄어드는지와 결과가 안정되는지를 보고 수치 허용 범위를 정한다. 현재 보고된 최대 차이 8.5×10⁻⁴를 그대로 합격 기준으로 복사하지 않는다. [PyBaMM 솔버 허용오차 설명](https://docs.pybamm.org/en/pybamm-v26.8.0.0/source/examples/notebooks/performance/05-solver-tolerances.html)

전체 해 연결과 last_state 연결은 10조각에서 비교한 상태 차이가 0으로 보고됐다. last_state 방식 100조각의 RSS는 약 286.04→286.16 MB였고 보관 해의 상태값 수는 6,156개로 일정했다. 이를 단기 메모리 검증 통과로 기록한다. 다음 100 EFC 실험에서는 Parquet 저장·체크포인트·진단이 포함된 상태의 RSS, 보관 객체 수, 캐시 크기도 측정한다. 물리 상태와 운전 장부를 디스크에 저장했다가 복구한 결과까지 확인해야 재시작 검증이 끝난다.

8. 기준시험으로 Q₀와 SOH 확보

기준시험은 25°C에서 1.5 A로 4.2 V까지 충전하고, 4.2 V를 유지해 전류가 0.05 A가 되면 종료한다. 4시간 휴지 후 0.5 A로 2.5 V까지 방전한다. 이 마지막 방전 구간의 Qref=∫I dt/3600을 구하며 Discharge capacity [A.h]를 사용할 때도 구간 끝값−시작값을 사용한다. 누적 용량의 최종 값 하나로 대체하지 않는다. 진단 CV의 0.05 A 종료와 일상 CV의 SOC 80% 종료는 별도 조건이다.

처음 기준시험의 결과가 Q₀다. 이 시험은 최초 상태를 복제한 분기에서 수행하고 본 궤적은 그 상태를 유지한다. 기준시험의 시간·Ah를 본 EFC에 더하지 않는다. 매 시험의 4시간 휴지는 이 프로젝트의 표준화 조건이며 원 논문이 모든 반복 시험에 적용한 조건으로 설명하지 않는다.

진단 전에는 본 상태와 장부를 보존한다. 복제 상태에서 시험을 실행한 뒤 본 상태·장부가 그대로인지 비교하고, 진단을 하지 않은 대조 계산과 같은 시점까지 재개했을 때의 결과도 비교한다. 메모리 공유로 원본이 변하거나 진단의 마지막 상태로 본 운전을 재개하면 실패다. 진단 분기의 절대 시간과 본 운전 시간이 섞이지 않는지도 확인한다.

첫 기준시험에서는 직접 적분과 누적 용량 차이를 같은 구간에서 대조하고 수치 해상도를 높였을 때 차이가 줄어드는지 확인한다. Q₀가 계산되기 전의 평형 창·부분 방전량을 대신 넣어 SOH와 EFC를 확정하지 않는다. 이 단계에서 처음으로 정확한 EFC 장부와 기준시험 레이블을 연결한다.

기준시험 시점은 0, 5, 10, 20, …, 100 EFC, 이후 매 10 EFC다. 목표 EFC가 방전 도중이면 해당 지점에서 진단하고 원래 단계의 나머지를 이어간다. EFC 0과 5의 상태도 보존해 초기 구간을 재계산할 수 있게 한다. 일반 체크포인트는 매 10 EFC와 종료 시 저장한다.

SOH 80%를 끼는 구간을 찾으면 이전 체크포인트에서 재계산해 1 EFC 간격으로 좁힌다. 마지막 SOH>80% 지점과 처음 SOH≤80% 지점을 함께 저장하고 레이블은 후자의 EFC로 정한다. 진단 간격보다 더 정밀하게 수명을 아는 것처럼 쓰지 않는다. 중간 점검을 늘리는 계산 비용도 실행 시간에 포함한다.

9. 5 EFC 초기 등급

초기 등급은 5 EFC의 절대 기준시험 용량 Q₅와 10초 DC 저항 R₁₀으로 정한다. R₁₀은 별도 복제 상태를 SOC 50%로 맞춘 뒤 30분 쉬고 5 A 방전을 10초 가해 구한다. R₁₀=(펄스 직전 전압−10초 시점 전압)/5 A다. Ω로 계산하고 mΩ로 표시한다. 0.10 V 감소는 20 mΩ다. 분극을 포함한 값이며 SEI 막 저항 하나와 같지 않다.

충전 전류의 영향을 줄이기 위해 최초 상태에서 분기한 1.5 A 공통 운전을 5 EFC까지 수행하고 원본 셀 등급을 한 번 정하는 설계안을 사용한다. 네 최적화 궤적은 각자 최초 상태에서 시작하며 등급 실험을 마친 노화 상태를 시작점으로 쓰지 않는다. 원본 cell_id는 공유하고 trajectory_id로 분기를 구분한다.

Q₅와 R₁₀의 33.3·66.7 백분위를 학습 셀에서만 정해 고정한다. A는 용량 상위 3분의 1이면서 저항 하위 3분의 1, C는 용량 하위 3분의 1이거나 저항 상위 3분의 1, B는 나머지다. 동점과 경계 포함 규칙을 설정에 남긴다. 경계가 겹치거나 차이가 수치 오차와 구분되지 않으면 등급 유효성을 확보하지 못한 것으로 보고한다. 등급 수를 억지로 균등하게 맞추지 않는다.

예비 9개 조합은 파라미터 변화가 용량·저항 차이로 나타나는지 확인하는 데 사용한다. 이 9개만으로 최종 등급 경계를 동결하지 않는다. 경계는 최종 학습 셀 기준으로 다시 산정해 검증·시험 셀에 적용한다. 등급은 이 가상 셀 집단의 초기 성능이며 제조사 인증이나 실제 팩의 안전 등급이 아니다.

10. 수명 레이블과 실패·중도 종료

각 전류 궤적의 첫 100 EFC가 입력이며 목표는 RUL=EOL_EFC−100이다. 총수명도 별도 저장한다. 예측은 같은 미래 운전과 고정 CC 설정을 유지한다는 조건이다. 첫 100 EFC만 계산해서 수명 정답을 얻은 것으로 처리하지 않는다.

한 셀·전류 궤적은 SOH 80%, 최대 3000 EFC, 누적 실행 시간 12시간 중 해당 종료 조건에서 멈춘다. 동시 실행은 한 건이다. 실행 시간에는 본 계산·진단·저장·재시작 후 사용 시간을 포함한다. 최대 EFC 도달 시 최종 진단을 완료할 수 있는지도 시간 예산에 포함해 관리한다.

종료 원인은 용량 수명 종료, 최대 EFC, 실행 시간 상한, 수치 오류, 물리 상태 한계, 운전 조건 미충족으로 구분한다. 최대 EFC·시간 상한은 수명을 아직 모르는 자료이며 그 종료 EFC를 EOL 레이블로 넣지 않는다. 기공률 소진이나 수치 오류도 SOH 80% 수명으로 바꾸지 않는다. 충전 시간 위반은 수명 레이블 관측 여부와 별도 필드다.

100 EFC 전에 수명이 끝난 사례는 완전한 입력을 가진 사례와 분리한다. 정확히 100 EFC에 종료돼 RUL=0이면 MAE에는 포함하고 MAPE 계산 불가 사례로 별도 집계한다. 첫 회귀 모델은 EOL이 관측된 사례로 학습하되 미완료 비율과 전류별 완료 분포를 함께 보고한다. 짧은 수명 셀만 남는 선택 편향을 숨기지 않는다. 계수를 임의로 키우거나 직선 외삽으로 정답을 만들지 않는다.

11. 저장과 시계열 압축

0~100 EFC의 일상 기록은 1초, 이후 일상 기록은 10초 간격이다. 전류 제어 단계 전환 직후 10초와 10초 DC 펄스는 0.1초 간격이며 기준시험은 1초다. 단계 전환 전후, CC→CV, SOC·전압 종료는 정기 시점과 무관하게 저장한다. 같은 시각의 전환 전·후 값은 이벤트 순서로 구분한다.

저장 주기는 솔버 내부 적분 간격이 아니다. 용량·에너지는 솔버 적분 상태로 계산하고 성긴 로그의 재적분으로 대체하지 않는다. 설치 버전의 t_interp 지원과 비용을 확인한다. 현재 보고된 실행 시간은 이 저장 규칙 전체를 포함하지 않으므로 저장 비용을 따로 측정한다.

충전·휴지·방전·휴지 한 묶음이 LSTM 한 시점이다. 충전·방전 각각 32개 시간 위치에서 전압·전류를 뽑고, 두 휴지는 각각 8개 위치의 전압을 사용한다. 기본 144개 관측값에 네 단계 시간, 충방전 Ah·Wh, CV 시간, 시작·종료 EFC, CC 설정값 12개를 붙여 156개 값으로 시작한다. 마스크는 별도 보관하고 정확한 열 순서와 스키마 버전을 고정한다.

실제 시간은 별도 특징으로 유지하며 단계 밖이나 불연속 전환을 가로질러 보간하지 않는다. CC와 CV의 경계에서 어느 구간의 값을 취했는지 구분한다. 첫 100 EFC가 주기 도중 끝나면 관측 부분만 쓰고 불완전 단계·주기의 마스크를 남긴다. 100 EFC 이후 값을 이용해 길이나 모양을 완성하지 않는다. 압축 32개와 64개 위치의 차이는 첫 학습 20개와 검증 자료에서 비교하며 시험 자료로 선택하지 않는다.

원시는 셀·전류·구간별 Parquet으로 저장한다. 모델 입력, 진단, 레이블, 파라미터·분할 메타데이터를 분리한다. 저장 후 다시 읽어 행 수·값·자료형·단위를 대조한다. 체크포인트는 원시 로그와 별개이며 물리 상태와 RunState를 모두 포함해야 한다.

12. 모듈과 입출력 계약

configs는 모델·운전·진단·셀 목록·분할·학습·최적화 설정을 보관한다. 환경 경로와 물리 실험 수치를 섞지 않는다. 같은 물리 값을 여러 모듈에 하드코딩하지 않는다.

simulation은 설정과 셀 파라미터를 받아 모델, SOC 경계 계산, 운전 제어, RunState, 복제 진단, 기록 저장을 수행한다. 출력은 본 궤적, 진단 결과, 체크포인트, 종료 상태, 실행 비용이다. 클라우드 학습 라이브러리에 의존하지 않는다. verify_chunking 같은 검증 코드는 이 모듈의 실제 제어·상태 전달 코드를 사용해 검증용 복제 구현과 본 구현이 달라지지 않게 한다.

dataset은 저장 기록과 셀 분할표를 받아 압축 입력, 마스크, 레이블, 스키마, 학습 전용 정규화 통계, 데이터 명세를 만든다. 내부 열화량과 미래 진단값을 모델 입력 파일에 함께 넣지 않는다. 검증·시험 통계로 정규화하거나 결측값을 채우지 않는다.

cloud_lstm은 내보낸 데이터 묶음만 읽어 Elastic Net·LSTM을 학습·평가하고 모델, 전처리 정보, 예측과 지표를 출력한다. train·evaluate·predict를 분리한다. 로컬 simulation 객체와 경로가 없어도 실행돼야 하며 명령 예시와 CPU·클라우드용 의존성 정보를 포함한다.

optimization은 질의한 후보의 첫 100 EFC 예측과 충전 시간 검사 결과만 받아 다음 후보·최종 추천·판단 보류를 출력한다. evaluation은 선택이 동결된 뒤 전체 정답으로 성능을 채점한다. 아직 질의하지 않은 시험 후보의 기록과 미래 EOL을 optimization에서 읽지 못하게 분리한다. serving_demo는 검증 후 클라이언트 입력과 서버 추론 결과를 연결한다.

원시 기록에는 cell_id, trajectory_id, 실험 종류, 분할, 본 시각, 단계·주기·이벤트, 설정 전류와 실제 전류, 전압, SOC, 온도, 누적 방전량·EFC, 종료 원인을 둔다. 진단에는 분기 시점, 진단 종류, Qref, SOH, R₁₀, 실패 원인을 둔다. 레이블에는 EOL 구간 양끝, 관측 여부, RUL, 중도 종료 사유를 둔다. 입력으로 허용한 열 목록을 명시해 다른 열이 자동으로 학습에 들어가지 않게 한다.

내부 단위는 s, A, V, Ah, Wh, K, m, m²/s, Ω다. 전류는 방전 양수·충전 음수이며 설정 전류 크기는 양수다. SOC는 0~1, SOH는 %로 열 이름에서 구분한다. 25°C=298.15 K, 5.86 μm=5.86×10⁻⁶ m, 0.020 Ω=20 mΩ, SOC ±0.1%p=±0.001을 확인한다.

환경변수는 BATTERY_DATA_DIR, BATTERY_OUTPUT_DIR, BATTERY_CHECKPOINT_DIR, BATTERY_MODEL_DIR 같은 경로와 BATTERY_DEVICE=cpu·cuda·auto에 사용한다. BATTERY_CLOUD_ENDPOINT는 후속 추론 주소다. 인증 키는 별도 비밀 환경변수로 두고 코드·데이터·로그에 저장하지 않는다. 난수 시드와 실험 수치는 설정 파일에 남긴다.

13. Elastic Net과 LSTM

두 모델은 같은 첫 100 EFC 정보를 사용한다. 입력은 전압·전류·단계·시간·EFC·CC 설정이다. 온도는 고정 조건이므로 메타데이터에 둔다. 반지름, SEI 확산계수, 내부 열화량, 미래 Qref·EOL, 초기 등급을 첫 비교의 입력에 넣지 않는다. 기준 모델은 전류별 학습 RUL 중앙값이다.

Elastic Net은 압축 특징을 정해진 EFC 구간별로 요약한 고정 길이 입력을 사용한다. 구간 구성과 규제 강도 탐색 범위는 작게 정해 기록하고 검증 자료로 선택한다. 다른 모델보다 더 긴 미래 구간을 주지 않는다.

LSTM 기본 구현은 PyTorch 단층, 은닉 32다. 마지막 유효 시점의 출력 뒤에 별도 Dropout 0.2와 RUL 회귀 출력을 둔다. 단층 nn.LSTM의 dropout 인수만으로 대체하지 않는다. 해당 인수는 층 사이에 적용된다. [PyTorch LSTM 문서](https://docs.pytorch.org/docs/2.14/generated/torch.nn.LSTM.html)

목표값은 RUL/1000, Huber delta는 0.1로 두어 원 단위 100 EFC에 대응시킨다. Adam 학습률은 0.001, 배치는 궤적 16개, 최대 300 epoch다. 시퀀스 내부 시간 순서는 유지하고 원본 셀별 학습 가중치가 비슷하게 되도록 구성한다. 입력 정규화는 학습 관측값만 사용하며 패딩·누락값을 제외한다.

검증 MAE가 5 epoch 동안 1 EFC 이상 개선되지 않으면 학습률을 절반으로 줄이고 최저 1×10⁻⁵로 둔다. 초기 20 epoch 이후 20 epoch 동안 같은 기준으로 개선되지 않으면 조기 종료한다. 저장 모델은 실제 검증 MAE가 가장 낮은 epoch로 복원한다. MAPE도 기록한다. 고정 시드 세 개로 반복해 평균과 변동을 보고하며 시험 결과로 시드나 체크포인트를 고르지 않는다.

14. 베이지안 최적화

각 가상 셀의 동일 최초 상태에서 전류별 독립 궤적을 계산한다. 한 후보의 평가는 첫 100 EFC를 관측하고 수명을 예측하는 것이다. GP 입력은 CC 전류 하나, 커널은 RBF다. 커널과 관측 잡음은 학습·검증 자료에서 정하고 최종 시험에서 고정한다. 잡음은 예측 잔차로 산정하며 목표 MAE 100 EFC를 표준편차로 대입하지 않는다. μ와 σ의 수명 단위를 일치시키고 분산 인수에는 그 단위의 제곱을 사용한다.

첫 후보는 3.0 A와 3.3 A다. 3.1·3.2 A 중 UCB=μ+2σ가 큰 쪽을 세 번째로 평가한다. 기본 예산은 서로 다른 후보 3개, 최대 4개이며 동률이면 낮은 전류를 먼저 선택한다. 세 번째 뒤 첫 100 EFC의 시간·목표 SOC 조건을 통과한 후보 중 가장 큰 LCB=μ−2σ가 양수이고, 남은 후보의 UCB가 그 값의 1.05배 이하이면 종료한다. 그렇지 않으면 마지막 후보까지 평가한다.

실패 후보도 예산을 한 번 사용한다. 3.0 A가 시간 조건을 실패해도 수명 관측값을 0으로 만들지 않는다. 물리 데이터와 수명 예측이 유효한지, 추천 가능한지를 구분한다. 최종 추천은 평가했고 초기 시간·SOC 조건을 통과한 후보 중 마지막 관측까지 반영한 GP 사후 평균이 가장 큰 전류다. UCB는 다음 탐색 후보 선택에만 쓴다. 유효 후보가 없으면 판단 보류 또는 추천 가능 후보 없음으로 반환한다.

이미 계산한 후보는 캐시로 재사용할 수 있지만 동일 후보를 다시 평가한 것처럼 이중 집계하지 않는다. 시험 중에는 질의된 후보의 결과만 공개한다. 캐시 사용 시에도 논리적 후보 평가 수와 실제 추가 실행 비용을 나눠 기록한다. 미질의 후보의 실패 여부를 미리 읽어 탐색을 유리하게 만들지 않는다.

첫 100 EFC에서 통과한 충전 시간 조건이 수명 전체에서도 유지되는지는 최종 미래 평가에서 확인한다. 한 번이라도 60분을 넘으면 추천 실패다. μ±2σ를 보장된 95% 신뢰구간으로 설명하지 않는다. 네 후보 전수 비교와 같은 3개 예산의 무작위 선택을 기준으로 성능·비용을 비교한다. 학습용 전체 수명 자료와 최종 정답 확인 비용은 탐색 예산과 별도로 집계한다.

15. 예측·추천 평가 기준

수명 예측 목표는 MAE≤100 EFC와 MAPE≤15%를 모두 만족하는 것이다. 같은 셀의 여러 전류 오차를 먼저 평균하고 셀 사이에서 다시 평균한다. 전류별·RUL 구간별 지표, 평가 가능 셀 수, 관측 완료 비율을 함께 보고한다. RUL=0은 MAPE에서 계산 불가로 별도 집계하고 MAE에는 포함한다. 0<RUL≤100 EFC의 큰 비율 오차도 원래 값과 사례 수를 보고한다. 분모를 임의로 바꾸지 않는다.

추천의 정답은 수명 전체의 모든 충전이 60분 이내인 후보 중 실제 RUL이 가장 긴 전류다. 선택이 동결된 뒤 미래 정답을 연다. 손실률은 (최선 실제 RUL−추천 실제 RUL)/최선 실제 RUL×100이다. 목표는 시간 위반 0건, 평균 손실률≤5%, 추천의 90% 이상이 최선 수명의 95% 이상, 유효 후보가 있는 셀의 추천 제공률≥90%다.

손실률은 조건을 충족한 추천에만 계산하되 전체 셀 수, 유효 후보가 있는 셀 수, 실패·판단 보류 수를 함께 표시한다. 시간 위반 후보의 긴 수명으로 음수 손실률을 만들지 않는다. 미완료 후보가 최선일 수 있으면 그 셀의 최적값·손실률은 평가 불가다. 최선 RUL이 0인 경우도 비율 계산 불가로 별도 처리한다. 성능이 좋은 완료 사례만 골라 전체 성능처럼 표시하지 않는다.

압축 방식, 학습 설정, 등급 경계, GP 설정, 종료 규칙을 동결한 뒤 최종 시험 40개를 평가한다. 학습·검증·시험의 원본 셀 ID가 겹치지 않는지 내보내기와 로딩 단계에서 각각 확인한다. 같은 분할과 같은 유효 사례로 모델을 비교한다.

16. 클라우드 학습과 원격 추론

클라우드는 학습 시간 단축과 차량 내부 컴퓨터가 무거운 추론을 맡지 않는 구성을 보여주기 위해 사용한다. 속도 향상은 실측할 결과다. 같은 데이터·설정으로 CPU와 선택한 클라우드 환경의 전처리, 학습, 전송, 비용을 나눠 측정한다.

cloud_lstm 전달 묶음에는 입력·마스크·레이블, 셀 분할표, 특징·단위 스키마, 학습 정규화 파일, 설정, 의존성, 실행 명령, 모델과 평가 형식을 포함한다. PyBaMM Solution이나 로컬 시뮬레이션 객체 없이 학습·평가·예측할 수 있어야 한다. GPU 제공자와 배포·요금 방식은 후속 선택 사항이다.

원격 추론 시연은 설계안으로 유지한다. 차량 역할의 CPU 클라이언트가 검증된 관측 기록과 적용 전류 조건을 보내고 서버가 압축·정규화·예측한 RUL_EFC, 입력 기준 EFC, 조건 전류, 모델 버전, 처리 상태를 반환한다. 업로드 크기, 왕복 시간, 서버 추론 시간, 클라이언트 RAM을 측정하며 연결 실패 상태를 표시한다.

첫 시연의 추천 전류는 가상 셀별로 검증·저장한 비교 결과와 연결한다. 실제 차량 한 대의 과거 기록을 다른 전류에서 관측한 기록으로 바꿔 넣지 않는다. 현재 상태에서 아직 사용하지 않은 전류의 미래를 비교하는 기능은 별도 검증이 필요하다. 가상 단일 셀 결과를 실제 팩 수명·안전 검증이나 남은 주행거리·일수로 확대하지 않는다.

17. 계산 예산과 다음 실행 순서

제공 기록에서는 한 주기의 모사 시간 1.81시간을 계산하는 데 실행 7.42초, 즉 모사 1시간당 약 4.11초가 걸렸다. 첫 빌드와 eSOH 계산을 포함하지만 규정된 저장·진단·체크포인트 비용은 빠져 있다. Q₀도 아직 없으므로 이 기록에서 환산한 100 EFC 약 21분, 3000 EFC 약 10시간은 초기 비용 추정으로만 남긴다. 실제 12시간 안에 수명 정답을 얻는다는 결론이 아니다.

200개×네 전류를 모두 한 개씩 실행해 각 12시간을 쓰면 9600시간, 400일이다. 이 값은 최대 계산 비용이며 현재의 예상 기간이 아니다. 과거 옵션의 속도를 사용한 약 267일 추정도 새 환경의 실측 일정으로 재사용하지 않는다. 반복 진단, 출력, 재시작, 노화 후 솔버 부담을 포함한 비용으로 실행 계획을 갱신한다.

다음 단계는 기준값 셀 한 개의 분할 수렴성 확인과 기준시험 Q₀ 확보다. CC 구간의 변수별 시작·끝 연결, CC→CV 전환 상태, 진단 후 본 상태 불변, 직접 적분과 용량 차이, 디스크 재시작을 확인한다. 이미 통과한 짧은 시험을 수정 없이 반복하기보다 남은 검증을 추가한다.

그다음 예비 9개 조합의 짧은 운전·5 EFC 등급 시험으로 SOC 정확도와 용량·저항 분리 가능성을 확인한다. 기준값 셀의 네 전류를 각각 100 EFC까지 실행할 때는 정확한 Q₀, 반복 진단, 규정 저장, 체크포인트를 포함한다. 시간 조건, SOH 감소율, 계산 시간, RSS, 출력 크기, 미완료 가능성을 측정한다. 첫 충전에서 실패한 3.0 A도 비교 자료로 보존한다.

이 결과로 실행 비용과 정답 확보 가능성을 확인한 뒤 학습용 20개로 연결을 확장한다. 20개×네 전류가 모두 12시간을 쓰면 상한은 960시간, 약 40일이다. 처음 완료한 궤적부터 EOL 관측과 비용을 점검하며 한도에 닿은 사례를 EOL로 만들지 않는다. 정답 확보가 어렵거나 비용이 일정에 맞지 않으면 200개를 자동 실행하지 말고 자료 수·계산 방법·환경 변경안을 근거와 함께 제시한다. 3000 EFC·12시간·동시 실행 한 건의 합의는 별도 결정 없이 변경하지 않는다.

확대 가능성이 확인되면 학습 40→80→120개와 검증 40개로 학습 곡선을 보고 설정을 동결한다. 이후 최종 시험 40개, 베이지안 최적화 평가, 원격 시연과 화면 연결을 진행한다. 정확한 솔버 허용오차와 메시, Elastic Net의 작은 탐색 범위 같은 구현 수치는 검증 근거를 남겨 정한다. 새 사용자 목표를 임의로 추가하지 않는다.

18. 오류 재현과 산출물

실행 기록에는 코드 버전, 환경, 셀·전류·시드, 적용 설정, 직전 체크포인트, 단계·EFC·시각, 실패 상태 범위, 예외와 실행 비용을 남긴다. 같은 입력과 환경에서 재현한 뒤 원인을 좁힌다. 파일 잠금·권한·저장 공간, 처리 속도·솔버 수렴, Solution·배열·리스트·캐시의 RAM 사용을 구분해 확인한다. 조건을 바꿔 오류가 사라진 것을 기존 사례의 수정으로 처리하지 않는다.

파일은 임시 경로에 기록하고 검증 후 완성 파일로 교체한다. 체크섬, 완료 여부, 마지막 유효 구간을 명세에 남긴다. 재시작 때 EFC·시간·행이 중복 누적되지 않게 하고 다음 셀 실행 때 이전 셀의 큰 객체 참조를 정리한다. 코드나 파일을 삭제해야 한다면 재현 근거와 기존 결과를 먼저 보존한다.

첫 단계 완료 산출물은 기준시험·분할 수렴성·상태 보존·메모리·재시작의 보고서와 실행 명령이다. 전체 첫 버전 완료는 작은 자료가 설정→시뮬레이션→진단→저장→압축→학습→예측→추천 평가까지 재현되는 상태다. 성능 목표 통과 여부는 별도로 보고한다. 구현 완료와 MAE·MAPE 목표 달성을 같은 말로 쓰지 않는다.

이 수정본을 실제 docs/modeling_decisions.md에 반영할 때는 현재 기준, 소스 확인, 실행 보고, 남은 검증을 구분한다. 폐기 실험과 삭제 이력은 별도 변경 기록으로 옮겨 현재 기준의 앞부분을 차지하지 않게 한다. 이미 확인한 사실은 필요한 코드·로그·설정의 근거 경로로 연결하고, 아직 검증하지 않은 항목에는 완료 표시를 붙이지 않는다.
