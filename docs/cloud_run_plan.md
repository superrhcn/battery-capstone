# 클라우드 100 EFC 실행 계획

작성일: 2026-10-28. 오늘은 기준 셀 4번에서 네 충전 전류의 초기 100 EFC를 비교한다. 200개 셀 전체 수명 계산과 학습은 이 예비실험 뒤에 진행한다.

## 1. 완료한 준비와 아직 하지 않은 작업

완료: 원본을 건드리지 않는 작업용 복사본, 소스·설정 분리, Git 제외 목록, 물리 계산용 의존성 목록, 새 100 EFC 실행기 구현. 로컬 ×1에서 새 프로세스 재개·진단 상태 보존·Parquet 왕복 검증을 통과했고, ×4에서는 셀 4번·3.3 A·0.05 EFC 짧은 계산을 마쳤다. ×4 완전한 주기나 100 EFC를 마쳤다는 뜻은 아니다. [실행기 검증 기록](runner_validation_2026-10-28.md)

공개 소스 저장소 [battery-capstone](https://github.com/superrhcn/battery-capstone)을 생성했고 파일 업로드를 진행 중이다. AWS 로그인과 예산 설정도 완료했다.

미완료: 전체 파일의 원격 반영 확인, EC2 인스턴스 생성, Linux 설치·재개 검증, 병렬 처리량 측정, 네 전류 100 EFC, 결과 보고서. 현재 문서는 실행 지침이며 100 EFC 실험 결과가 아니다. 계정 정보나 인증키는 코드·설정 파일에 저장하지 않는다.

## 3. CPU 서버를 먼저 검토하는 이유

현재 실행기는 CPU 기반 IDAKLU로 물리 방정식을 푼다. GPU를 연결했다고 이 계산이 자동으로 빨라지지는 않는다. 네 전류를 독립 프로세스로 나누는 것부터 측정한다. PyBaMM의 OpenMP 예시도 여러 입력의 계산을 분배하는 방식이며, 단일 계산에 스레드 수를 늘리는 것만으로 효과가 생긴다고 설명하지 않는다. 설치 버전은 현재 검증한 26.8.0.0을 유지한다. [PyBaMM 공식 병렬 계산 예시](https://docs.pybamm.org/en/v25.12.0/source/examples/notebooks/performance/07-multithreading.html)

우선 검토할 AWS 사양은 `m7i.2xlarge`의 8 vCPU·32 GiB RAM이다. GPU는 없다. 네 궤적의 메모리를 함께 담을 여유를 먼저 확보하려는 선택이며, 아직 이 계정에서 생성 가능하거나 가장 빠르다고 실측한 사양은 아니다. 계정 할당량·리전·현재 요금을 확인한 뒤 확정한다. [AWS M7i 사양](https://aws.amazon.com/ec2/instance-types/m7i/)

사용자 총예산은 약 한 달 동안 600,000원이다. AWS에는 `capstone-total-USD350`을 2026-10-28~2026-11-28 사용자 지정 기간으로 만들었다. USD 350은 환율·세금 등을 포함해 60만원과 정확히 같은 금액이라는 뜻이 아니다. 실제 사용액 50·80·100% 알림 설정과 별개로 메일 수신 확인은 남아 있으며, 자동 중지·종료 Budget Actions는 설정하지 않았다. 이 예산은 강제 지출 상한이 아니다.

현재 시급·환율·스토리지·전송료를 확인하지 않았으므로 완료 비용을 단정하지 않는다. 인스턴스 생성 전에 `예상 인스턴스 시간 × 시간당 요금 + 스토리지·전송료`를 계산하고, 실제 진행 속도로 남은 비용을 갱신한다. 실행기의 12시간 상한도 해당 Python 프로세스를 제한할 뿐 EC2를 자동으로 중지하지 않는다. 서버 종료는 별도로 관리한다.

## 4. 실행 전 통과할 단계

1. 설치: Python·OS·패키지 버전을 결과에 남긴다. 물리 계산 전용 의존성은 `requirements-simulation.txt`를 사용한다. Linux에서 같은 버전을 설치하고 계산할 수 있는지 확인한다.
2. 단일 주기: 셀 4번 ×4, 한 전류로 충전·휴지·방전·휴지를 완주한다. 실제 CV 진입, SOC 오차, 전압 경계, 시간·전하량 연결, NaN/무한대를 확인한다.
3. 기준시험: 초기 Q₀를 새 실행 환경에서 확보하고, 방전 전류 적분과 구간 누적 용량 차이를 기존 검증 기준으로 대조한다. 같은 메시에서 생성한 상태를 복제하여 진단하고, 본 상태벡터·장부 변화가 0인지 확인한다.
4. 저장·재개: 전체 해 대신 마지막 물리 상태와 장부·설정 식별자를 저장한다. 완전한 주기가 끝난 지점에서 재개한 결과가 연속 계산과 기존 분할 검증 허용오차 내에서 같은지 확인한다. EFC 경계가 방전 중간에 오면 새 충전으로 잘못 재시작하지 않는다.
5. 동시 2건: 서로 다른 전류·결과 폴더·프로세스로 짧게 실행한다. 합산 RAM, 궤적당 속도, 전체 EFC/시간, 저장 충돌을 측정한다. 각 프로세스의 OMP·BLAS 스레드는 우선 1개로 제한한다.
6. 동시 4건: 2건보다 전체 처리량이 증가하고 RAM 부족·스왑·수치 실패가 없을 때 확대한다. 오히려 느려지면 2건으로 유지한다.
7. 100 EFC: 위 항목을 통과한 실행기로 네 궤적을 실행한다. 완료·실패·시간 상한 종료를 구분하고, 중간 결과를 보존한다.

두 궤적을 동시에 계산할 때도 한 셀 안의 시간 순서는 유지한다. 충전 이후 상태가 다음 휴지·방전의 입력이다. 시간 구간을 임의로 독립 분할하지 않는다.

## 5. 실행기 연결 계약

실행기 `simulation/run_100efc.py`를 구현했다. CLI는 `--cell`, `--current`, `--mesh-scale`, `--efc`, `--output-dir`, `--resume`, `--smoke-cycle`, `--max-wall-s`다. `--max-wall-s` 기본값은 43,200초이며 재개 이전 시간을 포함한 누적 실행 상한이다. 다음 명령은 실행 방법이며, 이미 100 EFC를 완료했다는 뜻은 아니다.

```text
python simulation/run_100efc.py --help
python simulation/run_100efc.py --cell 4 --current 3.0 --mesh-scale 4 --efc 100 --output-dir outputs/pilot100/cell4_3p0A
```

각 전류는 고유 폴더를 사용한다. 3.1·3.2·3.3 A도 각각 별도 폴더를 지정한다. 새 실행기는 `--output-dir`로 경로를 받는다. `.env.example`은 자동으로 로드되지 않는다.

`--smoke-cycle`은 완전한 부분 주기 하나를 끝내고 재개 가능한 상태로 멈춘다. 같은 셀·전류·격자·목표 EFC·코드·설정·의존성 버전으로 동일한 출력 폴더에 `--resume`을 추가하면 `checkpoint.pkl`에서 이어간다. 이 체크포인트는 전체 실행 이력 대신 마지막 물리 상태와 장부를 보관한다. pickle은 실행 가능한 형식이므로 이 실행기가 만든 신뢰하는 파일만 읽는다. 코드·설정·패키지 식별자가 달라지면 재개를 거부한다. Windows에서 만든 체크포인트를 Linux에서 사용하는 교차 환경 재개는 검증하지 않았다.

## 6. 저장할 데이터와 보고서

본 운전은 주기별 Parquet에 시간 s, 전류 A, 전압 V, 온도 °C, SOC, 단계, EFC, 누적 용량 등을 저장한다. SOC는 물리 계산의 정답값, EFC는 운전 메타데이터이며, 저장된 모든 열을 그대로 ML 입력에 넣는다는 뜻은 아니다. 기준시험은 별도 진단 데이터로 두어 본 운전 전하량과 섞이지 않게 한다.

현재 일반 운전 출력은 1 s 간격이며 이벤트 끝점과 단계 경계의 중복 행도 포함한다. 적분·특징 추출 때 단계와 조각 식별자를 사용해야 한다. 전환 구간의 0.1 s 출력은 아직 없고, 기준시험도 설정 파일의 1 s를 적용하지 않아 Experiment 기본 출력 간격을 사용한다. 긴 전체 상태 이력을 RAM에 모으지 않고 구간별로 디스크에 기록한다.

진단 시점은 0, 5, 10, 20, …, 100 EFC다. Qref/Q₀로 SOH를 구하며, 진단 이후 본 운전의 상태·EFC가 변하지 않는지 확인한다. 100 EFC로 잘라 끝낸 방전은 SOC 20% 종료 검사에서 제외하고 별도 표기한다.

보고서는 네 전류에 대해 Q₀, SOH 변화, 20→80% 충전시간·CV 시간, 60분 제약 위반 횟수, 최대 SOC 오차, 실패 사유, 실제 실행시간, 최대 RAM, 저장 용량을 비교한다. 실행 환경·코드 버전·설정 해시와 재개 여부도 기록한다.

100 EFC 결과만으로 SOH 80%까지의 총수명 연장이나 LSTM 정확도를 입증하지 않는다. 이번 보고서에서 내릴 결론은 초기 열화의 관측 차이, 60분 충전 제약, 200개 셀 계산에 필요한 처리량·메모리 추정이다.
