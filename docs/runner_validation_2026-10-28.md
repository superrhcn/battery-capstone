# 100 EFC 실행기 검증 기록 — 2026-10-28

**실행기는 구현했고, 로컬 ×1 통합 검증과 ×4의 0.05 EFC 짧은 계산을 마쳤다. 네 전류의 100 EFC 실험과 AWS Linux 실행은 아직 완료하지 않았다.** 원본 프로젝트 대신 분리한 작업용 복사본에서 검증했다.

| 방전 중간 진단 | 0.1·0.2·0.3 EFC에서 목표 도달, 진단 후 상태·장부 보존 |

×1 방전 중간 진단을 넣은 계산과 대조 계산의 최종 차이는 SOC 5.515e-10, 전압 9.668e-09 V, 열화량/Q₀ 1.049e-09였다. 진단을 위해 방전을 끊었다가 새 충전으로 잘못 전환하지 않고 이어가는 경로를 확인했다.

Parquet를 다시 읽어 적분한 값과 장부의 차이/Q₀는 방전 2.976e-15, 충전 5.765e-06였다. 조각 내부 최대 저장 간격은 약 1.000 s다. 단계 전환의 중복 시각은 조각별로 구분한다.

초기 기준시험에서는 전류 적분과 누적 용량 차이가 약 10⁻¹⁵ Ah 수준에서 일치했고, 이후 기준시험도 약 10⁻¹⁴ Ah 이내였다. 두 기준시험 모두 종료 조건을 충족했고, 진단 뒤 본 상태와 장부는 바뀌지 않았다.

## 3. 100%를 조금 넘은 SOH를 처리하는 방법

0.05 EFC 기준시험의 Qref는 5.074061118 Ah, SOH는 **100.000599411%**였다. Q₀보다 약 0.030414 mAh 큰 값이다. 이 값을 100%로 잘라 저장하지 않는다.

이 차이를 배터리 성능 회복이나 수명 연장 성과로 해석하지 않는다. 진단 시작 상태 차이와 수치 오차 등의 영향을 구분하려면 추가 확인이 필요하다. 후속 100 EFC 보고서에도 측정 원값과 기준시험 조건을 함께 남긴다.

## 4. 파일과 재개 규칙

- 본 운전 관측값은 `cycle_000001.parquet`처럼 주기별로 저장한다. 시간·전류·전압·온도·단계·조각·SOC·EFC·누적 용량을 구분한다. SOC는 물리 정답값이며 모든 저장 열을 ML 입력으로 쓰는 것은 아니다.
- `diagnostics.json`은 기준시험 결과, `summary.json`은 궤적 요약, `checkpoint.pkl`은 마지막 물리 상태와 장부를 보관한다. 원시 결과와 체크포인트는 Git 업로드 대상이 아니다.
- `--smoke-cycle`로 완전한 주기 끝에서 멈춘 후, 같은 실행 인자와 출력 폴더에 `--resume`을 추가하면 이어간다. 코드·설정·의존성 식별자가 다르면 재개를 거부한다.
- pickle은 실행 가능한 형식이다. 이 실행기가 생성한 신뢰하는 체크포인트만 읽는다. Windows→Linux 교차 환경 재개는 검증하지 않았다.
- `--max-wall-s` 기본값은 43,200초다. 감시 프로세스는 멈춘 계산 호출도 종료할 수 있지만, AWS 인스턴스 자체를 중지하는 기능은 없다.

## 5. 남은 제한과 다음 검사

현재 본 운전은 1 s 출력에 이벤트 끝점과 단계 경계 중복 행을 포함한다. 0.1 s 전환 구간 기록은 미구현이다. 기준시험은 설정 파일의 1 s를 적용하지 않고 Experiment 기본 출력 간격을 사용하며, 이를 결과 메타데이터에 명시했다.

다음은 Linux의 같은 버전 설치·짧은 계산·자체 체크포인트 재개, 동시 2→4건 처리량·RAM 측정, 네 전류 100 EFC다. 100 EFC 결과만으로 총수명 연장이나 LSTM 정확도를 주장하지 않는다. 200개 셀 전체 수명, 장기 격자 비교, LSTM·Elastic Net·베이지안 최적화는 별도 단계다.
